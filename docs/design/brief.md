# PGS Design — актуальный бриф

Обновлён: 2026-09-09. Владелец финального визуального решения — пользователь; когда он делегирует выбор, ведущий агент выбирает сам и объясняет решение.

## Характер

PGS — профессиональная система управления строительством. Интерфейс должен выглядеть собранным, современным и выразительным: ясная иерархия, аккуратная кириллица, плотные полезные данные, спокойные поверхности и редкие латунные акценты. Пользователь ценит композицию, чувство материала и детали, но неоднократно просил уменьшать шрифты, приглушать выделение и упрощать декор.

Выразительность создают пропорции, свободное пространство, типографика, ритм данных и характерные для задачи представления. У всех модулей общий визуальный язык, но график, документы и снабжение не обязаны иметь один макет. Асимметрия допустима, если поддерживает приоритеты и имеет ясные оси; случайные смещения и разная высота однотипных элементов — дефекты.

## Текущие принятые решения

Это база для продолжения работы, а не запрет на будущий редизайн по новому запросу.

| Область | Принято |
|---|---|
| Навигация | Компактная общая верхняя шапка; PGS открывает глобальное меню; пять групп разделов, полный каталог и поиск по клику |
| Фон шапки | Равномерный `rgba(8,10,11,.84)` без градиента, blur и светлой нижней линии |
| Выделение | Нейтральное белое 3% hover / 5% active-open, без рамки, радиус 6px; при открытой группе одна заполненная заливка |
| Выпадающие панели | Тёплый `#f4f2ed`, глобальное меню `#f4f3ef`; без зеленоватого оттенка |
| Акценты | Латунь `#92713e`, светлая `#ceb27c`, глубокая `#654b29`; спокойный champagne `#f3ecdf` |
| Шрифт | Текущий Arial / Helvetica с полноценной кириллицей; компактный масштаб. Новую гарнитуру выбирают как отдельное решение с проверкой кириллицы, чисел и условий использования |
| Кнопки | Графитовая основная; вторичная с тонкой границей; небольшие скругления. Семантические состояния читаемы |
| Геометрия | Структурные области преимущественно прямые; контролы 6–7px; большие информационные блоки 14–18px по назначению |
| Интервалы | Связанные блоки 16px, на телефоне 12px; самостоятельные зоны обычно 24–32px. Не суммировать margin и gap без причины |
| Логотип | Rhythm: латунный знак + светлые PGS. Контуры букв из текущего SVG; общий scale `.81`, компенсированный stroke `25.555556`, маска `compact-3`. Контейнер 88px / 76px на телефоне. Не увеличивать шрифты меню при изменении логотипа |
| 3D | Доступен в навигации, без дублирующей отдельной иконки. Реальная модель проекта и демонстрационный пример обозначаются корректно |

Последнее пользовательское решение важнее старых макетов, советов ИИ-ролей и этой таблицы. При изменении значимого правила обновляй его здесь; не превращай хронологию всех экспериментов в инструкции.

## Порядок работы

### Точечное изменение

Найди нужный элемент в текущем интерфейсе и его основной стиль. Внеси правку, посмотри результат на затронутом экране и проверь смежное состояние, если оно зависит от изменения. Сохрани утверждённые пропорции и поведение. Не требуй заново бриф, три концепции или разрешение на уже порученное действие.

### Крупное изменение композиции или нового модуля

Зафиксируй пользователя, его задачу, основное действие и данные, с которыми он работает. Выбери 3–5 содержательных референсов: подпиши, какой принцип берёшь из каждого. Покажи три разных визуальных направления на одном сценарии и одинаковых данных; различай иерархию и взаимодействие, а не только цвета. Используй инструменты визуального проектирования; одних описаний трёх вариантов недостаточно, если пользователь просит увидеть дизайн.

Оцени варианты по удобству главной задачи, выразительности, плотности данных, читаемости и реализуемости. При делегированном выборе выбери сильнейший. Перенеси его в рабочую реализацию и проверь реальные состояния. Развивай выбранное решение последовательно, а не смешивай все варианты в одном экране.

## Граница авторского решения

- Не превращай каждый показатель в отдельную карточку по умолчанию. Используй строки, таблицы, шкалы времени, схемы зависимостей и рабочие панели там, где они подходят задаче.
- Декоративный градиент, стекло, анимация или новая иконка должны иметь понятную роль; сами по себе они не делают интерфейс дороже.
- Сохраняй понятные названия, смысл цветов, единицы измерения, клавиатурный фокус и доступ к главным действиям.
- Не прячь ошибки данных ради красивого снимка. Абстрактные архитектурные иллюстрации не выдаются за BIM-модель объекта.
