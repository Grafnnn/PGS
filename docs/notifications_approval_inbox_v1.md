# Notifications & Approval Inbox v1

## Назначение

`/inbox` собирает в одну персональную очередь решения и сигналы по всем проектам, к которым у пользователя есть доступ. Экран не заменяет реестры проекта: он показывает, что требует внимания сейчас, и ведёт в исходную рабочую зону.

## Источники v1

- активный шаг процесса согласования;
- действие проекта, ожидающее согласования;
- заблокированное или просроченное действие;
- отправленное изменение к договору без отдельного workflow;
- отправленное договорное обязательство без отдельного workflow;
- отправленная заявка на оплату.

Если изменение или обязательство связано с workflow, Inbox показывает один активный шаг процесса, а не дублирует предмет согласования.

## Права и решения

- список проектов ограничен членством пользователя;
- OWNER и ADMIN видят управленческие согласования и могут принимать решения;
- MANAGER видит назначенные его роли шаги workflow и операционные блокеры доступных проектов;
- VIEWER не получает действий, которые требуют прав на изменение;
- approve, revision и reject отправляются в существующие защищённые API исходного модуля;
- revision и reject требуют комментарий;
- исходные API повторно проверяют роль, состояние записи и конкурентное изменение;
- управленческие решения пишутся в audit log исходного модуля;
- личные read/snooze/archive-настройки не засоряют историю проекта.

## Персональное состояние

Для каждого пользователя отдельно сохраняются:

- прочитано / непрочитано;
- отложено до выбранной даты;
- архивировано.

Ключ элемента состоит только из разрешённого типа источника и его идентификатора. Перед изменением состояния сервер повторно проверяет, что активный источник существует в доступном пользователю проекте.

## Навигация

- пункт `Inbox` доступен в основном меню;
- колокольчик в верхней панели показывает количество непрочитанных активных элементов;
- переход из Inbox открывает проект сразу на соответствующей вкладке через параметр `tab`;
- неизвестное имя вкладки безопасно заменяется обзором проекта.

## Ограничения v1

- Inbox агрегирует активную работу, а не хранит отдельные копии бизнес-сущностей;
- завершённый или отменённый источник исчезает из активной очереди после обновления;
- автоматическая email/push-доставка не входит в v1;
- массовое согласование намеренно не добавлено: каждое управленческое решение подтверждается отдельно.
