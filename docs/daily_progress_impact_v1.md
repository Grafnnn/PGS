# Field Operations & Daily Progress v1

## Назначение

Контур продолжает существующий `Field Mobile / Offline v1`: прораб фиксирует смену, менеджер проверяет рапорт, владелец или администратор утверждает его. После утверждения пользователь отдельно просматривает и подтверждает влияние факта на связанные модули.

Никакие данные графика, материалов или действий проекта не меняются при открытии страницы, заполнении черновика, синхронизации с устройства, проверке или простом утверждении рапорта.

## Структурированный факт

В ежедневном рапорте доступны:

- измеримые работы: профессия, работа, объём, единица и человеко-часы;
- необязательная явная связь работы со строкой графика;
- полученные и израсходованные материалы из номенклатуры проекта;
- техника: количество единиц, машино-часы и часы простоя;
- свободный текст по выполненным работам, проблемам и простоям;
- фото и документы через существующую offline-очередь.

Строка работы без связи с графиком остается подтвержденным фактом ФОТ и выработки, но не меняет график. Система не выполняет неявное сопоставление по названию.

## Preview и применение

Для проверенного или утвержденного рапорта доступен `GET /api/daily-reports/:reportId/impact`. Preview показывает:

- изменение фактических объёмов и статусов графика;
- создаваемые записи факта выполнения;
- поставку и расход материалов;
- трудозатраты и профессии;
- машино-часы и простой;
- позиции, связанные с ВОР и потенциально готовые для КС;
- действие по проблемам или простоям;
- предупреждения и блокеры.

Запись выполняется только через `POST /api/daily-reports/:reportId/impact` с телом:

```json
{ "confirmed": true, "fingerprint": "<fingerprint из preview>" }
```

Условия commit:

1. пользователь имеет право редактировать проект;
2. рапорт имеет статус `approved`;
3. все явные ссылки существуют;
4. единицы структурированных материалов совпадают с номенклатурой;
5. preview не содержит блокеров;
6. fingerprint совпадает с текущим состоянием связанных данных;
7. пользователь подтвердил применение в интерфейсе.

Если после preview изменились связанные строки графика или материалов, commit возвращает конфликт и требует повторно проверить влияние. Так подтверждение пользователя всегда относится к тем значениям, которые он видел.

## Идемпотентность и аудит

- рапорт атомарно переводится из `pending` в `applying`, затем в `applied`;
- повторный запрос не увеличивает объёмы повторно;
- каждая запись выполнения хранит `sourceDailyReportId` и номер исходной строки;
- уникальный индекс не допускает дублирование одной строки рапорта;
- график, материалы, действие по отклонению, состояние рапорта и audit trail записываются в одной транзакции;
- при ошибке транзакция полностью откатывается.
- уже утвержденные до миграции рапорты получают `not_applicable`: они остаются в истории, не попадают в новую очередь и не могут задним числом удвоить ранее внесенный вручную факт.

## Связанные модули

- **График:** увеличивается `actualQty`; безопасно обновляется статус.
- **ФОТ / выработка:** утвержденные строки продолжают формировать фактические нормы производительности.
- **Материалы:** увеличиваются `deliveredQty` и `consumedQty`.
- **КС:** работы графика, связанные с ВОР, становятся кандидатами для расчетов приемки.
- **Риски / Claims:** проблемы и простой создают контролируемое действие в проекте.
- **Approval Inbox:** проверенные рапорты появляются на утверждение, утвержденные с непримененным фактом — как требующие внимания.

## Ограничения v1

- автоматическое сопоставление по похожим названиям намеренно отсутствует;
- разные единицы материалов не конвертируются автоматически;
- исправление уже примененного факта требует отдельного будущего adjustment workflow;
- live AI и provider-вызовы не используются;
- миграция должна применяться стандартным `prisma migrate deploy` перед использованием endpoint.
